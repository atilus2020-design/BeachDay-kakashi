Setup and deploy guide

This guide takes you from a fresh copy of Beach Day to a live site with sign-in and the Agents page. Plan for about an hour the first time. You need a GitHub account, a Netlify account and a Supabase account. The Free plans of all three are enough.

Never paste a real secret key, token or password into a chat, an issue, or this repository. Put them only in the places this guide names.

Part 1: Run it on your computer with mocks

Mocks are fake upstream services, so you can run the app without any real keys. You need Node.js 20 or later and Git.

  1. On GitHub, open the Beach Day repository, then click Fork.
  2. In a terminal, clone your fork and install the packages. Replace <your-user> with your GitHub user name: 
    git clone https://github.com/<your-user>/BeachDay-kakashi.git
cd BeachDay-kakashi
npm install
npm run build:agents
  3. In the first terminal, start the mock services and leave them running. They listen on http://127.0.0.1:9100: 
    npm run mocks
  4. In a second terminal, in the same folder, load the test settings and start the app: 
    set -a; source tests/mocks/test.env; set +a
npm run dev
  5. Open http://localhost:8888 in your browser. You should see the beach picker and a score.

If npm run dev stops with fetch failed after it loads the functions, use the offline form that the browser tests use. It does not need access to Netlify:

set -a; source tests/mocks/test.env; set +a
npx netlify dev --offline --port 8888

Part 2: Create the Supabase project

Supabase provides sign-in and the roles table. Create the project in the Supabase dashboard.

  1. Go to supabase.com/dashboard, click New project, and choose a name, a region near Florida and a database password. Save the password in a password manager. Wait until the project is ready.
  2. Open Project Settings → API Keys. Copy the Project URL and the publishable key. Keep them for Part 6. Do not copy any secret key.
  3. Open Authentication → Sign In / Providers → Email. Turn on Email and Confirm email, and set the minimum password length to 12. Save.
  4. Open Authentication → URL Configuration. Set Site URL to your production address, for example https://your-site.netlify.app. You can change it once Netlify gives you the address in Part 4.
  5. In Redirect URLs, add exactly these two entries, and no others. Replace the host with your site address: 
    https://your-site.netlify.app/login/
https://your-site.netlify.app/login/reset/

    Do not use wildcards (**). Do not add localhost to this production project. For local sign-in, use a separate development Supabase project.

  6. Open SQL Editor, click New query, paste the contents of each file in the supabase/migrations/ folder in the repository, in name order, and click Run. The migration creates the profiles table, its row security rules and the sign-up trigger.

Part 3: Set up Google sign-in (optional but recommended)

Skip this part if you want email sign-in only. The Agents page works with either.

  1. Go to the Google Cloud Console. Create a project if you do not have one, then open APIs & Services → Credentials.
  2. Click Create credentials → OAuth client ID. Choose Web application.
  3. Under Authorized JavaScript origins, add only your site origin, for example https://your-site.netlify.app.
  4. Under Authorized redirect URIs, add only the Supabase callback. Replace <project-ref> with the reference in your Project URL: 
    https://<project-ref>.supabase.co/auth/v1/callback
  5. Click Create. Copy the client ID and the client secret.
  6. In Supabase, open Authentication → Sign In / Providers → Google. Turn it on, paste the client ID and the client secret, and save. The client secret goes only into Supabase. Never put it in Netlify or in the repository.

For the Google sign-in details, see the Supabase Google guide.

Part 4: Create the Netlify site from GitHub

  1. Sign in at app.netlify.com and click Add new project → Import an existing project.
  2. Choose GitHub, authorise Netlify if asked, and select your fork of BeachDay-kakashi.
  3. Leave the build settings as Netlify reads them from netlify.toml: build command npm run build and publish directory dist.
  4. Click Deploy. The first deploy may fail until you add the variables in Part 6. That is expected.
  5. Copy your site address (it ends in .netlify.app). Go back to Supabase Part 2, step 4, and set the Site URL and the redirect URLs to this address.

Part 5: Create the GitHub token

Beach Day commits approved changes with a fine-grained personal access token. The token can reach only this one repository.

  1. On GitHub, click your profile photo, then Settings → Developer settings → Personal access tokens → Fine-grained tokens. Click Generate new token.
  2. Set Resource owner to your account. Under Repository access, choose Only select repositories and pick your fork.
  3. Under Permissions, set Contents to Read and write and Metadata to Read-only. Set nothing else. In particular, do not add the Workflows permission.
  4. Set an expiry, for example 90 days, and add a reminder to rotate it before then.
  5. Click Generate token and copy it now. GitHub shows it only once. You will paste it into Netlify in Part 6.

For more detail, see the GitHub guide to fine-grained tokens.

Part 6: Set the environment variables in Netlify

Netlify reads these values at build time and when functions run. Set each one in the Netlify UI, never in a file in the repository.

  1. In your Netlify site, open Site configuration → Environment variables.
  2. For each row in the table below, click Add a variable, enter the name and value, and choose the scope and context shown. Use your own values. The example formats are fake.
  3. Click Save after the last variable.
  4. Open Deploys, then click Trigger deploy → Deploy site. Variables take effect only in a new deploy.

Part 7: Check the deploy

  1. Open Deploys in Netlify and wait until the latest deploy shows Published.
  2. Open your site address. The beach picker and the score should load.
  3. If the deploy failed, open its log. A missing variable is the most common cause. Check Part 6, then trigger a new deploy.

Part 8: Sign up and become super_admin

Anyone can create an account, but only one account is the super_admin. You make that account by hand.

  1. Open https://your-site.netlify.app/login/ and choose Sign up. Enter your email and a password of at least 12 characters.
  2. Open the confirmation email and click the link. The email comes from Supabase, and the built-in email service sends only 2 emails an hour. If you hit that limit, wait an hour, or set up custom SMTP in Supabase.
  3. In Supabase, open SQL Editor, click New query, and run this. Replace you@example.com with the email you signed up with. The statement is the promotion SQL from the migration, which only works once the email is confirmed: 
    update public.profiles p set role = 'super_admin'
from auth.users u
where p.id = u.id and u.email = 'you@example.com' and u.email_confirmed_at is not null;
  4. Check that the result says UPDATE 1. Any other count means the email is wrong or not yet confirmed.
  5. Sign out and sign in again. The Agents page should now open.

To remove someone's access, run the same kind of statement with role = 'user'. Keep the number of super_admin accounts to one unless you decide otherwise.

Part 9: Smoke test

  1. Open the home page and pick a beach. Check that a score, a label and a reason appear.
  2. Open /api/forecast?beach=south-beach. It should return JSON with status 200.
  3. Open /how-it-works/ and /resources/. Both should load with the footer.
  4. Open /agents/ as the super_admin. The agent list should load.
  5. Optional: install the app on your phone from the browser's share menu.

Part 10: Rotate secrets

  1. GitHub token: create a new fine-grained token with the same settings (Part 5), replace GITHUB_TOKEN in Netlify, trigger a deploy, then delete the old token in GitHub.
  2. Anthropic key: create a new key in the Anthropic console, replace ANTHROPIC_API_KEY in Netlify, trigger a deploy, then revoke the old key.
  3. If you think a secret leaked: revoke it at its source first, then follow the steps above. Check the GitHub commit history for anything you did not expect.

If something goes wrong

  • The deploy fails. Open its log. A missing variable is the most common cause. Check Part 6, then trigger a new deploy.
  • Local run stops with fetch failed. Use the offline command from Part 1: npx netlify dev --offline --port 8888.
  • Sign-in or the reset link fails. Check that the Redirect URLs in Supabase match your site address exactly, including the /login/ and /login/reset/ paths and no trailing wildcard.
  • Sign-in fails after a long pause. A Free Supabase project is paused after one week without activity. Restore it from the Supabase dashboard. Read Supabase on pausing free projects.
  • No confirmation email arrives. The built-in email service sends 2 emails an hour. Wait, or set up custom SMTP in Supabase.
  • The Agents page says you have no access. Only the super_admin account can open it. Check Part 8, then sign out and sign in again.

Free plan notes

  • Supabase pauses idle projects. A Free project is paused after one week without activity. When it is paused, sign-in and the Agents page fail, but the public beach pages still work. Restore the project from the Supabase dashboard. Read Supabase on pausing free projects.
  • Supabase email limit. The built-in email service sends 2 emails an hour, which covers sign-up confirmations and password resets for a small group. For more, configure custom SMTP. See Supabase Auth rate limits.
  • Netlify credits. Each approved change triggers one build, and builds use Free plan credits. Keep builds rare. The Netlify rate limiting guide explains how request limits apply.
